## frontend-web — Playwright scaffolded but NOT wired

`frontend-web/playwright.config.mjs` exists:

- `testDir: './tests/e2e'` — **this directory does not exist**. Only
  `tests/unit/` (152 spec/test files + fixtures/README, Vitest) and `tests/integration/`
  (2 files: `referrals/outbox-referral-live.test.ts`,
  `profile/partial-update.test.ts`) are present. `npx playwright test` would
  collect zero specs.
- `baseURL`: `process.env.E2E_BASE_URL || 'http://localhost:4028'`
- `webServer`: `npm run dev` (Next dev) with `reuseExistingServer: true`,
  120 s startup timeout — skipped entirely when `E2E_BASE_URL` is set
  (pointing at an already-running stack).
- Projects: `chromium-desktop` (Desktop Chrome) + `mobile-chrome` (Pixel 7).
- Trace on first retry; screenshots + video on failure. GitHub reporter in CI.

**Gaps:**
- `playwright` / `@playwright/test` is **not in package.json** (npx resolved
  playwright@1.63.0 on demand). No `test:e2e` script either.
- No auth fixture, no `storageState`, no test users anywhere under
  `frontend-web/tests`. Auth in the app is cookie-session via middleware +
  Bearer token to API routes; a real e2e login would go through `/login`
  against local Supabase — see "Shared dev credentials" below.

- `baseURL`: `process.env.E2E_BASE_URL ?? 'http://127.0.0.1:8083'` (Expo web).
- `webServer`: `CI=1 npm run web` (Expo export for web) on :8083, with env:

  - `EXPO_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321`
  - `EXPO_PUBLIC_SUPABASE_ANON_KEY=e2e-anon-key` (deliberately fake — see below)

- 45 s test timeout, 10 s expect timeout, workers: 2.

  devDependency here (unlike frontend-web).

### Auth strategy (mobile) — 100% route-mocked, no live backend

`tests/e2e/helpers/auth.ts`:
- `mockAuth(page)` — `page.route` intercepts `**/auth/v1/token**`,
  `**/auth/v1/logout**`, `**/auth/v1/user` and `**/rest/v1/user_profiles**`
  and fulfills fabricated Supabase responses. No real GoTrue needed.
- `seedSession(page)` — `addInitScript` writes a fabricated session into
  `localStorage` under `paymax_secure_sb-127-auth-token` and
  `paymax_secure_sb-wnicsubiznmishkmunsv-auth-token` (the app's
  secure-storage key prefix + Supabase host keys).
- `mockPinStatus(page, hasPin)` — stubs `GET /api/v1/transfers/pin/status`
  AND seeds `localStorage.paymax_mock_txn_pin` (the app gates all money
  routes behind a transaction-PIN check; `TEST_TXN_PIN = '1234'`).
- `loginAs(page, user, {withPin})` — composes all three and lands on
  `/home` (or `/services/bills` to exercise the PIN gate).

`tests/e2e/fixtures/users.ts` — three fake personas (never real accounts):
`funded` / `unfunded` / `lockedPin`, emails `*.qa@paymax.test`, tokens like
`e2e-funded-access-token`. `fixtures/billers.ts` + `providerResponses.ts`
hold biller/payment mock data; `helpers/testData.ts` re-exports all of it.
`helpers/common.ts` `mockAmbientRequests()` stubs ambient calls
(`utility/logos`, `visitor/notifications`, `elections/active`,
`beneficiaries`, `modules/visibility`). ~69 `page.route(...)` call sites
suite-wide; specs like `modules/voting.spec.ts` stub their own endpoints
because voting is live-by-default (`EXPO_PUBLIC_VOTING_USE_MOCK` unset=false).

Implication: the mobile suite validates UI flows against contracts, **not**
the real API — a production-validation run still needs a live-backed pass.

## frontend-admin — no e2e at all

No `playwright.config`, no playwright dependency, no e2e specs. Vitest unit
tests only (`vitest.config.ts`, `middleware.test.ts`, `*.test.ts(x)` beside
sources under `app/` and `src/`). Admin auth gate = `user_profiles.role`
(see `src/features/auth/`). Any admin e2e is greenfield.

## Repo-level scripts

- `smoke.sh` (repo root) — read-only curl liveness vs local Docker stack,
  `BASE` default `http://localhost:8080`: `GET /api/v1/public/health`→200,
  `POST /api/auth/{login,register}` empty→400, `GET /api/auth/me`→401,
  `GET /api/admin/users` no-key→401. Safe anywhere; exits non-zero on fail.
- `TEST_ENDPOINTS.sh` (repo root) — **NOT read-only**: performs real writes
  (saved listing, saved search, support ticket) against Marketplace/Voting.
  Requires `BEARER_TOKEN=<supabase-jwt>`, `API_BASE` default
  `http://localhost:8080/api/v1`. Staging/local only, never production.
- `scripts/dev/ensure-dev-login.sh` — canonical local-login repair. Converges
  the shared fixture accounts to one documented password
  (`DEV_LOGIN_PASSWORD`, default `LocalDevAdmin123!`) and repairs all three
  gates: GoTrue credential, `platform_users` lockout
  (`status`/`failed_login_attempts`/`locked_until`), `user_profiles.role`
  (admin console gate). Default accounts: `admin@spotlight.internal`,
  `qa-claude-test@spotlight.internal`. **Use this — never hand-reset.**

## Env vars used by existing e2e

`E2E_BASE_URL` (both configs — bypass webServer), `TEST_TXN_PIN` (mobile
helper constant `'1234'`, not an env var), plus the four `EXPO_PUBLIC_*`
values the mobile config injects into its webServer. No `E2E_*`/`TEST_*`
credential env vars exist anywhere — nothing performs a real login today.

## Summary of gaps for production e2e

1. Web has a config but no specs, no dep, no auth fixture → greenfield;
   reuse mobile's `page.route`+`seedSession` pattern OR drive the real
   `/login` page against the `ensure-dev-login.sh` fixture accounts.
2. Admin has nothing → greenfield; admin login also flows through
   `admin@spotlight.internal` + `user_profiles.role='ADMIN'`.
3. Mobile specs exist but are hermetically mocked — production validation
   needs a live-backend lane (unset mocks, point `EXPO_PUBLIC_API_BASE_URL`
   at the target env) that does not exist yet.
