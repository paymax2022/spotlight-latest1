## Contract-vs-implementation delta (approximate)

Method + normalized path-shape equality; contract `servers:` URLs plus generic
mount prefixes tried per file; BFF catch-all proxies counted separately.

| Bucket | Ops | % |
|---|---|---|
| Concretely implemented in Go backend | 1,214 | 90.0% |
| Concretely implemented in Next.js BFF | 103 | 7.6% |
| Reachable only via a BFF catch-all proxy | 32 | 2.4% |
| Unmatched in either surface | 0 | 0% |

Reverse delta: **1,698 unique backend paths are absent from all contracts**
(of 2,752) — i.e. the contracts document only ~1/3 of the registered Go
surface. The contract files fully covered by the Go backend: academy,
associations, doctor, invest, intake, property, restaurant, transport,
connect-phase1-safety. Estate (46 ops) and visitor (49 ops) contracts are
implemented entirely on the **Next.js BFF**, not the Go backend.

Known drifts (details in `inventory-delta.txt`): nutrition contract ops land on
`/api/arena/nutrition/*` and a BFF catch-all rather than the declared
`/api/v1|/api/finance` mounts; several `voting.openapi.yaml` admin paths are
implemented under `/api/connect/admin/contests/*`.

## Caveats

- `scan-gin-routes.mjs` is a heuristic source scanner (masks comments/strings,
  resolves `Group()`/`Register*` call chains); it is not a Go compiler. Flag-gated
  or pool-nil-gated routes still appear — the CSV lists *registered-in-code*
  routes, not *mounted-at-runtime* ones.
- The delta is approximate by design: path-shape matching only, no auth/flag
  state, and BFF catch-alls can forward paths that ultimately 404.
