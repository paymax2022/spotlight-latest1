# Estate UAT Gap Analysis — M15 Announcements & communication · M16 Emergency incident & crisis management · M17 Reports, analytics & exports · M18 Notifications, inbox & reminders

Source spec: `Estate_Visitor_Access_UAT_Workplan_Test_Cases.md` (20 Oct 2026), §M15 lines 2617–2725, §M16 lines 2726–2869, §M17 lines 2870–3013, §M18 lines 3014–3115.
Method: read-only inspection of the Go estate backend (`backend/internal/estate`, wiring in `backend/internal/app/finance_routes.go:1187–1466`, platform oversight in `estate_admin_routes.go`), the platform notification queue (`backend/internal/notifications/service.go`), the Next.js BFF the React Native estate screens actually call (`frontend-web/app/api/v1/estate/**`, `frontend-web/src/server/estate/**`), Supabase migrations, and the RN screens under `mobile-app/reactnative/app/{announcements,emergencies,reports,estate-notifications,guard}`. No code was modified.

**Architecture note (drives many verdicts):** estate functionality exists in TWO channels:
1. **Go backend** — feature-flagged, routes at `/api/finance/estate/:id/…` (fr). This is where the notification fan-out machinery lives: every event persists a row to `estate_notifications` and enqueues an **Expo push** via asynq (extras:137–156; wiring fr:1210–1246). SMS/email workers exist in the platform queue (notif:275–378) but **no estate call site ever requests them** (fr:1237 sends `ChannelPush` only).
2. **Next.js BFF** — `/api/v1/estate/*` and `/api/v1/visitor/*`, estate derived server-side from the caller (`resident.ts getResidentContext`, single-estate `limit(1)`). The React Native announcements/emergencies/reports/notifications screens call **this** channel (see `src/features/*/api.ts` API bases). BFF estate writes **insert rows only — no notification fan-out, no push at all** (push tokens are stored via `app/api/v1/notifications/push-token` with "no consumer anywhere", `src/server/wallet/notifications.ts:10–12`). `Idempotency-Key` headers sent by the mobile client (emergencies/announcements api `idem()`) are ignored by BFF routes.

Member notification **preferences are persisted but never consulted** at emit time on either channel — `notify()`/`notifyMembers()` (extras:137–183) read no settings row — so mute/opt-out has no effect anywhere. **There is no estate reminder scheduler**: the asynq poller registers only health reminder jobs (`backend/internal/app/scheduler_poller.go:45–49`); `RunMaintenanceAllEstates` (extras:441–443) is unwired, and `NotifPaymentOverdue`, `NotifMeetingReminder` (advance), `NotifElectionReminder/Result`, `NotifTaskOverdue`, `NotifRepairUpdate`, `NotifVisitorArrived/Denied/Overstayed` constants (extras:25–42) are **never emitted** (grep of call sites: only invoice-created, restriction, task-assigned, facility, announcement, emergency, meeting-created, vendor-assigned, ban/restore, transfer are used).
