# Estate UAT Gap Analysis — M19 / M20 / M21 / M22 / M23 (integration, security, device, platform, migration)

Source spec: `Estate_Visitor_Access_UAT_Workplan_Test_Cases.md` (20 Oct 2026 draft, lines 3116–3720).
Repo inspected at working tree of `/Users/paymax/Desktop/wordpress/spotlight/new`. All evidence paths relative to repo root.

Verdict rubric: **Implemented** = concrete, self-contained code evidence covering the acceptance result (mechanism verifiable in-repo, incl. unit/live-DB tests). **Partial** = meaningful code exists but the UAT acceptance result is not fully covered or is unproven without a live run. **Missing** = no code for the capability at all. **Not-verifiable-in-repo** = the case inherently requires a staging env / load lab / VAPT / device-browser lab and no decisive in-repo claim can be made — deliberately NOT marked Pass.

## What actually exists (baseline for these modules)

- **Platform estate-oversight admin surface** (read-only, RBAC-guarded): `backend/internal/app/estate_admin_routes.go` (mounted `finance_routes.go:1465`), slugs seeded by `supabase/migrations/20260919000000_estate_admin_rbac.sql`; admin console pages `frontend-admin/app/admin/estate/*` (gates, security, dues reconciliation, elections, visitor-logs, ops, content).
- **Per-estate admin + audit**: `backend/internal/estate/admin.go` (dashboard, ban/restore, config, `GetAuditLog` 219–245); immutable `estate_audit_log` (`supabase/migrations/20260623120000_estate_dues_money_path.sql:41–54`) written in-txn by `service_dues.go:578–594` (`auditTx`) and best-effort (`audit`).
- **Authorization model**: every estate service call re-checks live membership via `assertRoles` (member / banned / deleted / role) — `backend/internal/estate/service.go:1548–1573`; cross-estate isolation contracts in `backend/internal/estate/isolation_test.go:25–43`; RLS enabled on all estate tables (migrations `20260616250000_estate.sql` … `20260623120000…:68–80`).
- **Payment integration reliability**: Paystack dues checkout — idempotency key required, payer-scoped replay, verify-then-settle with amount check, atomic claim, self-heal poll (`backend/internal/estate/paystackcheckout/{service,repository}.go`), shared webhook with HMAC-SHA512 signature verification (`backend/internal/webhooks/webhooks.go:278–313`, `backend/internal/provider/paystack/paystack.go:452`); ledger + `estate_payments` unique idempotency index (`20260623120000…:10–15`, `service_dues.go:218,280,355–391`).
- **Offline gate sync (server side)**: idempotent bulk insert keyed on `client_id UNIQUE`, member-gated — `service.go:536–556`; consumed by oversight read `estate_admin_routes.go:241–258`.
- **Uploads/downloads**: backend-controlled presigned R2 PUT with content-type/extension allowlist and 10-min TTL; presigned GET 60-min with role check — `backend/internal/estate/presign.go`, `service_modules.go:478+`.
- **Auth middleware**: per-request live token validation against Supabase (rejects tampered JWTs), fail-closed account-status check (suspended/locked/deleted → 403), optional session-revocation check behind flag — `backend/internal/middleware/auth_context.go:35–137`. Rate limiter middleware exists (`per_user_rate_limit*.go`, `auth_rate_limit*.go`) and is applied to auth/transfer/vote/maps routes (`backend/internal/app/router.go:154–166`, `finance_routes.go:400–487`) — **but on no estate route**.
- **Maintenance jobs**: overdue invoices, auto restrictions, expired access codes — idempotent — `backend/internal/estate/service_extras.go:337–443`; PII-scrub soft delete `service_extras.go:298–335`.
- **Mobile**: RN estate screens carry `accessibilityLabel/accessibilityRole` (`mobile-app/reactnative/app/guard/*.tsx`, `app/visitor/*.tsx`, `app/estate-admin/index.tsx`, `app/emergencies/*.tsx`, `app/dues/index.tsx`); ₦ formatter `mobile-app/reactnative/src/features/visitor/utils/visitorFormatters.ts:6`. **No offline queue/draft persistence for estate flows** (an offline queue exists only for academy — `src/features/academy/offlineQueue.ts`).
- **What does NOT exist anywhere in the repo**: SMS provider integration for estate; virus/AV scanning; search indexer; CSV/report export for estate; legacy-data migration/import tooling (`scripts/` has none); reversible (down) migrations; maker-checker, impersonation, legal hold, suspicious-access alerting, role-based MFA, per-estate feature flags, platform merchant-application queue, estate-level suspension.
